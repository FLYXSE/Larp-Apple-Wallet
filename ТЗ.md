## 1. Общее описание

Мобильное приложение-клон Apple Wallet на SwiftUI: визуально и по взаимодействиям максимально приближенное к системному Wallet, но работающее автономно, без PassKit, без реальных платёжных систем и без сервера.

Ключевое отличие от оригинала — **демо-режим**: в приложение можно добавить несуществующую (выдуманную) карту и назначить её обложкой любое фото из галереи пользователя. Встроенный **симулятор Apple Pay** воспроизводит культовый сценарий оплаты: иконка оплаты → шторка Apple Pay → двойное нажатие кнопки → сканирование Face ID → наклон устройства → «оплата прошла».

Приложение полностью офлайновое: никакой сети, аналитики, аккаунтов. Все данные — локально на устройстве.

### 1.1 Границы проекта (out of scope)

Явно **не входит** в ТЗ:

- Реальные платежи, NFC-передача данных, эмуляция Secure Element.
- Использование фреймворка PassKit и системного `PKPaymentButton`/`PKPaymentAuthorizationController` (эмитация настоящего Apple Pay запрещена технически и не преследуется — смотреть §7).
- Публикация в App Store (сборка и распространение — только через GitHub Actions + сайдлоад).
- iCloud-синхронизация, Apple Watch, iPad-оптимизация.
- Системный перехват аппаратной кнопки Side/Power (см. ограничение §7.2).

Значения ниже — обязательные, извлечены из оригинального Wallet. Отклонения не допускаются без согласования.

### 3.1 Цвета

| Роль | Значение |
|---|---|
| Холст (главный фон) | `#000000` (именно чёрный, не `#1C1C1E`) |
| Surface 1 (панели, списки) | `#1C1C1E` |
| Surface 2 (pressed, inset) | `#2C2C2E` |
| Glass overlay (кнопки «+», тулбар) | `rgba(255,255,255,0.12)` |
| Hairline-разделитель | `#262629`, 0.5pt, inset 16pt |
| Основной текст | `#FFFFFF` |

Приложение всегда тёмное (`.preferredColorScheme(.dark)`), независимо от системной темы.

### 3.2 Типографика

| Элемент | Шрифт |
|---|---|
| Заголовок «Кошелёк» | SF Pro Display, 34pt, Bold |
| Заголовок шторки | SF Pro Display, 28pt, Bold |
| Заголовок раскрытой карты | SF Pro Display, 22–24pt, Semibold |
| Секции в списках | SF Pro Text, 13pt, Semibold, UPPERCASE |
| Body / строки | SF Pro Text, 17pt, Regular, tracking −0.4pt |
| Суммы, баланс, last4 | табличные цифры (`monospacedDigits` / SF Mono для маски номера) |
| Подпись на лице карты (держатель) | SF Pro Text, 13pt, Medium, UPPERCASE |

Правило переключения оси: SF Pro Display ≥ 20pt, SF Pro Text ≤ 17pt.

### 3.3 Геометрия карточек

- Ширина карты: экран − 16pt отступ с каждой стороны.
- Высота: 220pt (кредит/дебет), 280pt (посадочный талон), 200pt (лоялти).
- Corner radius: **10pt** — фиксирован для всех типов.
- Тень: `rgba(0,0,0,0.5) 0 8px 24px` + внутренний верхний хайлайн 0.5pt `rgba(255,255,255,0.08)`.
- **Peek-интервал стопки: 80pt** (на 375pt-устройствах — 72pt). Священная величина: не сжимать.
- Стопка — вертикальная, по центральной оси, без сеток и каруселей.
- Максимум видимых peek: 5, дальше — скролл.

### 3.4 Хром интерфейса

- **Нет таб-бара** — навигация это сама стопка.
- Сверху слева: «Кошелёк» (large title), сверху справа: круглая кнопка «+» 32×32pt, фон `rgba(255,255,255,0.12)`, глиф `plus` 16pt, тап-зона 44pt.
- Статус-бар светлый поверх чёрного фона.
- Без поисковой строки.

### 3.5 Моторика

| Действие | Параметры |
|---|---|
| Раскрытие карты | `.spring(response: 0.5, dampingFraction: 0.8)`, 0.5s; остальные карты уходят вниз `.easeInOut(0.4)`; контент под картой — fade-in с задержкой 200ms |
| Свёртывание | обратный spring, порог drag 60pt, rubber-band после 100pt |
| Тактильность | expand — `.impactOccurred(.medium)`, collapse — `.impactOccurred(.soft)`, смена карточки — `.selectionChanged()` |
| Успешная оплата | `.notificationOccurred(.success)` + звук-имитация (по желанию) |
| Появление шторки Apple Pay | карта «влетает» в центр, фон уходит в `#000000` |

## 4. Структура экранов и пользовательские сценарии

### 4.1 Карта экранов

```
App
└── WalletHome (корень)
    ├── CardStackView            — стопка карт
    ├── CardDetailView           — раскрытая карта (push/inline)
    ├── AddCardSheet             — «+» → добавление карты
    │   └── PhotoCropScreen      — выбор и обрезка фото обложки
    ├── EditCardSheet            — редактирование (swipe по карте / «...»)
    ├── SettingsSheet            — настройки симуляции оплаты
    └── PayButton (FAB)          — плавающая кнопка оплаты, правый нижний угол
        └── ApplePaySheet        — полноэкранная симуляция оплаты
```

### 4.2 Сценарий A — Главный экран (стопка)

1. Открывается на `#000000`, large title «Кошелёк», кнопка «+» справа сверху.
2. Карты расположены вертикально с peek 80pt; видны лицо карты, имя эмитента, логотип сети, маска `•••• 4521`.
3. Тап по карте → карта раскрывается до полного размера, остальные уходят вниз.
4. В развёрнутом виде: баланс/сумма крупно (SF Pro Display 40pt Bold), список «ПОСЛЕДНИЕ ОПЕРАЦИИ» (строки 60pt: иконка 32pt, название + дата, сумма справа), нижний тулбар 56pt на `.regularMaterial` с тремя круглыми кнопками 44pt (`creditcard.fill`, `list.bullet.rectangle`, `ellipsis`).
5. Drag-down по развёрнутой карте — свернуть обратно в стопку.
6. Пустое состояние: пунктирный контур карточки + текст «Нажмите +, чтобы добавить карту» + иконка.

### 4.3 Сценарий B — Добавление карты (в т.ч. несуществующей)

Шторка с формой. Поля:

| Поле | Тип | Валидация |
|---|---|---|
| Название карты | Text | обязательно, ≤ 30 символов |
| Номер карты | Text (keyboard `.numberPad`) | 16 цифр, форматирование `#### #### #### ####`, допускается заведомо фиктивный |
| Срок действия | Text | `MM/YY` |
| Имя держателя | Text | UPPERCASE, необязательно |
| Баланс / лимит | Text (decimal) | необязательно, формат по локали |
| Тип | Segmented | Кредит · Дебет · Транспорт · Талон · Лоялти |
| Цвет/градиент | Палитра-пресеты | 8 пресетов + «Свой цвет» (ColorPicker) |
| **Фото обложки** | `PhotosPicker` | любое фото из галереи; **свободный выбор, без ограничений** |

Требования к обложке:

- После выбора — экран обрезки: карточный кроп 1.586:1, pinch-zoom, pan, кнопки «Отмена»/«Готово».
- На лице карты поверх фото — затемняющий градиент (снизу вверх, 0.0→0.55) для читаемости текста.
- Фото хранится в `Documents/CardImages/<uuid>.jpg`, в JSON — только относительный путь; ресемпл при сохранении до maxWidth 1600pt, качество 0.85.
- Альтернатива фото (если пользователь отказал в доступе к фото или отменил выбор): оставить градиент-пресет — приложение не падает и не блокирует сохранение.

Сохранение → карта появляется **вверху** стопки, тактильный отклик.

Редактирование: те же поля + «Удалить карту» (с подтверждением `.confirmationDialog`).

### 4.4 Сценарий C — Симуляция Apple Pay (ключевой)

**Точка входа:** плавающая круглая кнопка 56×56pt в правом нижнем углу (над home-indicator, отступ 24pt), фон `rgba(255,255,255,0.12)` + blur, глиф `creditcard.fill` / `applelogo`-стиль 22pt. Тап-зона ≥ 56pt. Если карт нет — по тапу показывается алерт «Добавьте карту, чтобы оплатить».

**Шторка** — полноэкранный overlay с чёрным фоном (не обычный sheet с серым). Верхняя часть: мини-шторка «Отмена»/сумма/продавец; центр: выбранный платёжный метод (последняя использованная карта, свайп влево/вправо — выбор другой карты из стопки); низ: подсказка состояния.

Демо-данные: продавец «DEMO STORE», сумма — из настроек (по умолчанию `1 000,00 ₽`), можно менять в SettingsSheet.

**Стейт-машина (4 состояния):**

```
idle → awaitingDoublePress → faceID → holdNearReader → success
         ↘ cancel/timeout от любого состояния
```

| # | Состояние | Что видит пользователь | Условие перехода |
|---|---|---|---|
| 1 | `awaitingDoublePress` | Карта в центре, снизу — реплика боковой кнопки (тонкий прямоугольник справа у рамки экрана) + текст «Дважды нажмите кнопку, чтобы оплатить», анимация двойного подсвечивания кнопки | Двойное нажатие (§7.2) в окне ≤ 1.5 c |
| 2 | `faceID` | Панель Apple Pay: глиф Face ID + «Подтвердите лицом». Системный экран Face ID поверх приложения | Успешная `LAContext` → `holdNearReader`. Отказ + флаг «Требовать Face ID» → «Попробуйте снова». Недоступность (симулятор) → анимация ~1.2 c и переход (или ошибка по флагу) |
| 3 | `holdNearReader` | Текст «Приложите iPhone к считывателю», анимация волн NFC, лёгкий подъём карты к верху экрана | Обнаружен наклон устройства (§7.4) с удержанием ≥ 0.7 c |
| 4 | `success` | Зелёный круг 64pt `#30D158` с галкой, текст «Готово», хаптик `.success` | Автозакрытие через 1.5 c (или тап) |

**Дополнительно:**

- Свайп вниз / кнопка «Отмена» — выход из любого состояния с анимацией сброса.
- Таймаут на состоянии `holdNearReader` — 20 c → возврат в `awaitingDoublePress` с текстом «Повторите».
- В `success` в карточку добавляется транзакция: «DEMO STORE», сумма, дата «сейчас» — она появляется в «ПОСЛЕДНИЕ ОПЕРАЦИИ».
- Каждая стадия сопровождается звуком/хаптиком, имитирующим оригинал (двойной клик → тактильный «двойной» отклик, Face ID → тихий, успех → `.success`).

## 5. Модель данных

```swift
struct WalletCard: Codable, Identifiable, Equatable {
    let id: UUID
    var title: String              // "Моя карта", "Sapphire"
    var type: CardType             // .credit .debit .transit .boarding .loyalty
    var number: String             // 16 цифр, хранится как строка (демо)
    var expiry: String             // "MM/YY"
    var holder: String             // UPPERCASE
    var balance: Decimal?
    var coverImagePath: String?    // относительный путь в Documents/
    var gradient: [String]         // hex-цвета пресета (2–3 стопа)
    var network: CardNetwork       // .visa .mastercard .amex .mir .none
    var createdAt: Date
    var lastUsedAt: Date?
    var transactions: [Transaction]
    var sortOrder: Int             // порядок в стопке
}

struct Transaction: Codable, Identifiable, Equatable {
    let id: UUID
    var merchant: String
    var amount: Decimal
    var date: Date
    var category: String           // SF Symbol name, напр. "cart.fill"
}

enum CardType: String, Codable { case credit, debit, transit, boarding, loyalty }

struct AppSettings: Codable, Equatable {
    var amount: Decimal             // сумма демо-оплаты
    var merchant: String            // продавец для транзакции
    var requireFaceID: Bool         // блокировать оплату без успешного Face ID
    var useVolumeButtons: Bool      // аппаратный триггер по кнопкам громкости
}
```

Схема хранения:

```
Documents/
├── wallet.json                   // [WalletCard], atomic-запись
├── CardImages/<uuid>.jpg
└── settings.json                 // AppSettings; новые ключи — decodeIfPresent
```

Требования: атомарная запись (`Data.write(options: .atomic)`), миграция-заглушка при отсутствии/повреждении файла (пустой кошелёк вместо краша), обратно совместимое декодирование `AppSettings` (старый `settings.json` без новых ключей не теряет значения), операции сортировки и `lastUsedAt` обновляются при выборе карты для оплаты.

## 7. Технические ограничения симуляции (важно для реализации)

### 7.1 Никакой реальной оплаты

Симуляция не использует PassKit, NFC (CoreNFC) и эмуляет системный интерфейс **собственными SwiftUI-вьюхами**. Это демо-режим: он ничего не списывает и никуда не передаёт данные. В интерфейсе допусима строка-маркер «Демо» в шторке оплаты (маленький label, 11pt, `#636368`), чтобы не выдавать симуляцию за платёж.

### 7.2 Кнопка Side/Power не перехватывается iOS

Приложения **не могут** зарегистрироваться на нажатия боковой (включения) кнопки — системой она перехватывается целиком. Поэтому в ТЗ заложены два рабочих механизма:

1. **Основной (гарантированно работает везде, включая симулятор):** реплика боковой кнопки на экране шторки — справа от рамки, тонкий прямоугольник 4×60pt, анимация «подсветки» при распознавании **двойного тапа** по ней (интервал ≤ 0.4 c между тапами).
2. **Опционально (только физическое устройство):** наблюдение за изменением громкости через KVO над `MPVolumeView` — двойное нажатие кнопки громкости как аппаратный аналог. Включается переключателем в SettingsSheet «Аппаратные кнопки громкости». На симуляторе и при недоступности — тихо отключается, без крашей.

Оба механизма ведут в одно состояние `faceID`.

### 7.3 Face ID

Стадия `faceID` идёт через **системный Face ID**: `LAContext.evaluatePolicy(.deviceOwnerAuthenticationWithBiometrics)` — реальный системный экран аутентификации поверх приложения. На успехе оплата переходит в `holdNearReader`. При недоступности (симулятор, без enrolled Face ID) — анимация глифа ~1.2 c и переход дальше (или ошибка «Face ID недоступен», если включён флаг «Требовать Face ID»). При отказе пользователя + флаг «Требовать Face ID» — «Попробуйте снова». Без флага демо продолжает платёж после анимации (реалистичность UI, результат не блокирует).

Камера/`Vision` в оплате **не используются** — нет запроса `NSCameraUsageDescription` и нет крашей `AVCaptureConnection`.

**UI:** нижняя панель Apple Pay ( Pay), глиф Face ID + «Подтвердите лицом» на стадии, подтверждение боковой кнопкой до Face ID и после — «Приложите к считывателю».

### 7.4 Детект наклона

`CMMotionManager` (accelerometer, `deviceMotionUpdateInterval = 0.1`):

- Стартовое состояние запоминается при входе в `holdNearReader`.
- Переход в `success` если: `|pitch − pitch₀| ≥ 25°` (наклон верхней части к считывателю) **и** удерживается ≥ 0.7 c, **или** `rotationRate` превысил порог 1.2 rad/s и затем стабилизировался.
- Данные сглаживаются EMA (α = 0.2) — без фильтрации детект дёргается.
- При выходе из шторки датчик останавливается (`stopDeviceMotionUpdates`) — требование по батарее.
- Fallback (если датчик недоступен): длительное удержание пальцем на карте ≥ 1.5 c.

### 7.5 Анимация успеха

Зелёный `circle.fill` `#30D158` 64pt, галка белая, появление — scale 0.6 → 1.0 spring, + haptic `.notificationOccurred(.success)`.

### 8.2 `project.yml` (суть)

```yaml
name: AppleWalletClone
options:
  bundleIdPrefix: com.example
  deploymentTarget:
    iOS: "16.0"
  createIntermediateGroups: true
targets:
  AppleWalletClone:
    type: application
    platform: iOS
    sources: [Sources]
    settings:
      base:
        PRODUCT_BUNDLE_IDENTIFIER: com.example.walletclone
        MARKETING_VERSION: 1.2.0
        CURRENT_PROJECT_VERSION: 3
        INFOPLIST_FILE: Config/Info.plist
        INFOPLIST_KEY_UILaunchScreen_Generation: YES
        INFOPLIST_KEY_UISupportedInterfaceOrientations: UIInterfaceOrientationPortrait
        INFOPLIST_KEY_NSPhotoLibraryUsageDescription: "Выберите фото для обложки карты"
        TARGETED_DEVICE_FAMILY: 1
        SWIFT_VERSION: "5.9"
        CODE_SIGN_STYLE: Automatic
        ENABLE_BITCODE: NO
```

Требование: `xcodegen generate` должен работать **и локально, и в CI** без ручных действий. `.xcodeproj` в репозиторий не коммитится (в `.gitignore`).

### 8.3 Workflow `build-ipa.yml`

Триггеры: `push` на ветку `main` + `workflow_dispatch` с input `signing` (`signed` | `unsigned`, по умолчанию `signed`).

Шаги:

1. `actions/checkout@v4`
2. Выбор Xcode: `sudo xcode-select -s /Applications/Xcode_16.2.app` (закрепить версию!)
3. `brew install xcodegen` → `xcodegen generate`
4. **Если `signing == signed`:** импорт сертификата и профиля из GitHub Secrets по официальной схеме GitHub:
   - `BUILD_CERTIFICATE_BASE64` (`.p12` в base64)
   - `P12_PASSWORD`
   - `BUILD_PROVISION_PROFILE_BASE64` (`.mobileprovision` в base64)
   - `KEYCHAIN_PASSWORD` (временный keychain)
   - установка профиля в `~/Library/MobileDevice/Provisioning Profiles/`
5. `xcodebuild archive`:
   ```
   -project AppleWalletClone.xcodeproj
   -scheme AppleWalletClone
   -configuration Release
   -destination 'generic/platform=iOS'
   -archivePath build/App.xcarchive
   -allowProvisioningUpdates   # только для signed
   CODE_SIGN_STYLE=Automatic
   ```
   Для `unsigned`: добавить `CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY=""`.
6. `xcodebuild -exportArchive -archivePath build/App.xcarchive -exportPath build/ipa -exportOptionsPlist Config/ExportOptions-*.plist`  
   (для `unsigned` plist с `method: ` отсутствует — упаковка `Payload/App.ipa` вручную через `zip`, либо пропустить экспорт и упаковать содержимое архива).
7. `actions/upload-artifact@v4` — `AppleWalletClone.ipa` (retention 30 дней).
8. `if: github.ref == 'refs/heads/main' && github.event_name == 'push'` — опционально `softprops/action-gh-release` c тегом `build-${{ github.run_number }}`.
9. Cleanup `if: always()` — удалить keychain и профиль.

`ExportOptions-Development.plist`:

```xml
<key>method</key><string>development</string>
<key>signingStyle</key><string>automatic</string>
<key>teamID</key><string>$TEAM_ID</string>   <!-- подставляется через sed из секрета -->
```

### 8.4 Что должен уметь пользователь после сборки

- Скачать `.ipa` из Artifacts/Release.
- Установить через AltStore / Sideloadly / ESign / TrollStore (указать в README).
- При использовании бесплатного Apple ID: срок действия подписи **7 дней**, еженедельная переподпись — описать в README.
- Опционально: сгенерировать собственный самоподписанный сертификат и профиль (инструкция в README), положить в Secrets.

## 10. Приёмочные критерии (Definition of Done)

**Визуал**

- [ ] Фон `#000000`, никакого тёмно-серого.
- [ ] Стопка с peek ровно 80pt (72pt на 375pt), карта 10pt radius, тень 0.5/8/24.
- [ ] Заголовок «Кошелёк» 34pt Bold слева, «+» 32pt в кружке справа.
- [ ] Таб-бара нет. Никаких лишних хром-элементов.
- [ ] Списки — inset-grouped c hairline `#262629`, системные цвета.

**Функционал**

- [ ] Добавление карты с любым фото из галереи (включая выдуманный номер) работает; отказ в доступе к фото не ломает сценарий.
- [ ] Карта сохраняется между перезапусками; фото переживает перезапуск; порядок стопки сохраняется.
- [ ] Раскрытие/свёртывание карты — spring 0.5/0.8, хаптики по §3.5.
- [ ] Кнопка оплаты в углу присутствует и доступна на главном экране.

**Симуляция оплаты**

- [ ] Двойной тап по реплике кнопки (или по громкости при включённом флаге) переводит в состояние Face ID ≤ 1.5 c.
- [ ] Стадия Face ID идёт через системный `LAContext`; глиф + текст «Подтвердите лицом» на панели Apple Pay; флаг «Требовать Face ID» блокирует оплату при отказе.
- [ ] На симуляторе/без биометрии — анимация ~1.2 c и переход (или ошибка по флагу).
- [ ] Переход в «Приложите к считывателю»; наклон ≥ 25° с удержанием 0.7 c → успех.
- [ ] Успех: зелёный `#30D158`, хаптик `.success`, автозакрытие 1.5 c.
- [ ] Отмена (свайп/кнопка) и таймаут 20 c работают из любого состояния.
- [ ] После оплаты транзакция видна в «ПОСЛЕДНИЕ ОПЕРАЦИИ».
- [ ] Датчики (`CMMotionManager`, volume-observer) отключаются при закрытии шторки.
- [ ] На симуляторе весь сценарий проходится без физических датчиков (fallback-и работают).

**Сборка**

- [ ] `xcodegen generate && xcodebuild build` проходят локально без ошибок.
- [ ] GitHub Actions на `push` выдаёт артефакт `AppleWalletClone.ipa`.
- [ ] Режим `unsigned` собирается без Secrets; режим `signed` — с Secrets.
- [ ] README содержит: сборку, настройку Secrets, установку IPA, 7-дневный лимит бесплатной подписи.

**Качество**

- [ ] `swift build`/xcodebuild — 0 warnings по новому коду.
- [ ] Нет сетевых вызовов (grep по `URLSession|http` пуст).
- [ ] VoiceOver-подписи на всех интерактивных элементах.

| Риск | Влияние | Митигация |

| Изменения API GitHub Runners / Xcode на раннере | CI падает | Пиннинг версий Xcode и `runs-on: macos-15`, ручной триггер `workflow_dispatch` |
| Истечение 7-дневной подписи | Приложение перестаёт открываться | README: еженедельная переподпись (AltServer/AltStore) или свой сертификат в Secrets |
